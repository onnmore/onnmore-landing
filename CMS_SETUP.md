# CloudCannon CMS setup

This repository is configured for CloudCannon as a Git-backed CMS. CloudCannon
edits this repository; the website remains a static site and its existing
GitHub Pages deployment can continue serving the published files.

## Connect the repository

1. Sign in to CloudCannon and connect the GitHub repository
   `onnmore/onnmore-landing`.
2. Select `main` as the production branch and use the repository root as the
   site source. There is no local build command or generated output directory.
3. Keep the existing `onnmore.space` DNS and GitHub Pages publishing setup
   unchanged unless you intentionally decide to move hosting.
4. Use CloudCannon's Visual Editor for copy, page content and images. Review
   changes in a branch or pull request before merging them to `main`.

## Editing boundaries

The CMS exposes editorial pages, blog guides, news and the existing tools
collection.
Checkout, payment, customer portal, service-request and printing workflows
remain code-managed. The admin workspace and its Apps Script integration are
also code-managed and excluded from the editorial collection. `news/news.json`
and the news scripts are excluded because the JSON is generated by the
scheduled GitHub Actions workflow.
Tool pages contain application logic; changes to their behavior should be
reviewed as code even though the pre-existing tools collection remains
available in CloudCannon.

Plan prices and service identifiers are maintained in code and must remain
consistent across the visible plan cards, `assets/plan-catalog.js` and the
payment backend. Do not change one of these independently in the Visual
Editor.

CloudCannon account access, GitHub authorization and DNS are managed outside
this repository; no credentials or API keys belong in the CMS configuration.
